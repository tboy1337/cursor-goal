**Root cause**: At ~0:11 in HPC E01, cue 0 shows `MatmulCodeBlock` in a `PhaseLayer`, and cue 1 shows the same code (dimmed) with a terminal panel below — in a separate `PhaseLayer`. The cross-fade formula `fadeIn * (1 - nextFadeIn)` created a brightness dip: at the midpoint, both layers were at ~50% opacity, meaning the overlapping code block appeared at ~75% brightness before jumping back to 100%. This caused a visible "flash" that made the transition look fragmented.

**Fix**: Changed `usePhaseFade` across all 172 composition files from interpolated cross-fade to a **hold-until-covered** pattern:

- **Old**: `return fadeIn * (1 - nextFadeIn)` — both phases semi-transparent during transition, causing brightness dip
- **New**: `return fadeIn * (1 - nextFullyVisible)` — current phase stays at full opacity (1.0) while the next phase fades in on top; only drops to 0 after the next phase is fully opaque and covering it

This means:
- **Same visual content** between consecutive cues: zero visual change (perfectly seamless)
- **Different visual content**: smooth reveal of new content on top of old (no brightness dip)

Also updated all 8 generator scripts and the boilerplate template so future episodes use the new pattern.
